## "Предложить песню"
Подзаголовок: можно предложить до 10 песен. Об ограничениях тут [spec/suggest/limits.md](/spec/suggest/limits.md)
Если ограничения не стоит (undefined), то заголовок не отображается.
При достижении лимита возможность предложить песню блокируется до освобождения лимита при удалении песни администратором или до окончания ближайшего джема.

Если пользователь уже предложил сколько-то песен то подзаголовок: можно предложить еще J песен (уже предложено K)

### Елементы
Два отдельных текстовых поля: «Исполнитель» и «Название песни».
Использовать API для поиска и автокомплита через debounce по введенным данным. В выпадающем списке показываются исполнитель, название песни и, если возможно, превью трека. Выбор результата заполняет оба поля и сохраняет ID выбранного трека из API.
Если трек не найден в музыкальном сервисе, разрешен ручной ввод исполнителя и названия песни в те же два поля без ID из API.
Поле "ваша роль": необязательный выбор одной роли из [roles.md](/spec/roles.md). Можно предложить песню без собственного участия.
Роли в песне: список из дефолтных ролей на песню [roles.md](/spec/roles.md)
Они заданы для всех песен по умолчанию, количество 1 на каждую роль

Выбранная автором «ваша роль» занимает одно из заданных мест соответствующей роли, а не добавляет место сверх указанного количества. На автора распространяются общие правила и лимиты участия [/spec/participate/limts.md](/spec/participate/limts.md).

Замечание:
У песни минимально должен быть 1 гитарист/пианист и 1 вокалист.
Если человек пытается предложить песню без этого минимального критерия (например без музыкальных ролей вовсе) - всплывает сообщение об ошибке.
Минимальный критерий (или минимальный "рецепт" для песни) указывается/редактируется в админке [/spec/administration/index.md](/spec/administration/index.md)

Каждая роль это строка в которой: 
– Иконка роли c цветом роли определенным в UI теме
– Название роли текстом
– Количество - степпер с кнопками +,- (бывает так что нужно в песне 3 вокалиста например)
– кнопка(с иконкой без текста) удалить
После спика ролей кнопка "добавить роль".
Текстовое поле: ссылка на песню
Текстовое поле: тональность
Текстовое поле (textarea): комментарии
Обязательные текстовые поля: «Исполнитель» и «Название песни». Ссылка, тональность и комментарии необязательны. Отдельно проверяются минимальный набор ролей и общие ограничения на предложение песни и участие.
Кнопка "далее": доступна, но отправка выполняется только после заполнения обоих обязательных полей и прохождения проверок; при ошибке показывается всплывающее сообщение с причиной.
По нажатию предложенная песня добавляется в общий список песен на ближайший джем.

Если песня уже добавлена в список на ближайший джем - будет всплывать ошибка что такая песня уже есть и ссылка для перехода на карточку песни [/spec/participate/track-view.md](/spec/participate/track-view.md)
Дубли в пределах джема определяются так:

– Если у обеих записей есть ID трека из API, сравниваются ID. Одинаковые ID означают дубль; разные ID означают разные песни, даже при совпадающих названиях или исполнителях.
– Если хотя бы у одной записи нет ID из API, сравниваются только названия песен. Исполнитель в этой проверке не участвует. Совпадение названия считается дублем, даже если исполнители различаются.

История исполнений трека с ID из API связывается по этому ID; для ручного ввода используется название без исполнителя. Случай, когда ручная запись по названию совпадает с несколькими разными ID из API, требует отдельного решения о связи с историей.

Только после успешного добавления песни количество предложенных песен K увеличивается на 1, а оставшийся лимит J уменьшается на 1. Ошибка, обнаруженный дубль или повторная отправка того же предложения не расходуют лимит повторно.
Пользователь не может удалить песню из предложенных, это могут сделать только админы

### Потенциальные дубли

Во время ввода названия после debounce проверяется похожесть на названия песен, уже предложенных на текущий джем. При совпадениях показывается предупреждение «Возможно, эта песня уже предложена» со ссылками на карточки потенциальных дублей. Для различения записей в результатах показываются название и исполнитель, хотя похожесть определяется по названию.

Похожесть сама по себе не запрещает добавление песни. Проверка точных дублей по правилам выше остается обязательной: предупреждение не позволяет обойти запрет на точный дубль.

После добавления похожие песни рассматриваются как группа потенциальных дублей в пределах текущего джема. Группа может содержать больше двух песен. Ее песни получают отдельную маркировку «Возможный дубль» со ссылками на соответствующие карточки. Маркировка не меняет статус готовности состава, не объединяет песни и не связывает их истории исполнений.

Администратор рассматривает группу в [админке](/spec/administration/index.md#проверка-потенциальных-дублей): исключает песни, которые не являются дубликатами, и сохраняет оставшиеся в группе. Исключение из группы не удаляет песню из джема.

Стартовый порог похожести — 85%. Конкретный алгоритм сравнения, нормализация названий, длительность debounce и правила автоматического формирования групп пока обсуждаются и не зафиксированы. Правила обработки новых совпадений после проверки группы также требуют отдельного решения.
